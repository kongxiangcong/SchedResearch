# R13 合同：多 tile 模型中的完成事件与联合静态编译

日期：2026-09-08。状态：**方向与实验合同已确定，尚未实现或运行 R13 性能实验。** 本轮以硬件建模和仿真为研究方法，不要求 Wormhole 板卡。

## 1. 当前范围与历史关系

用户本次明确要求硬件模型研究。本文是后续 R13 的执行合同，取代 2026-09-07 proposal 与 R12 预登记中“必须先固定板卡、固件并通过 native G0 才能研究性能”的前置要求。Wormhole B0 是公开架构和接口的参考来源；我们研究的是一个显式定义的参考模型，而非声称逐周期复刻某个在售 SKU。

R1–R12 的原始报告、合同、代码、结果和 hash 不改。R12 的“native G0 未通过”保留为历史事实，但不构成 R13 的阻断；也不把它改写成已通过。活动进度见 [R1–R12 总览](../research_progress.md) 与 [候选回溯](../analysis/r1_r10_research_retrospective.md)。更新前两份文档的原字节快照在 [history](history/)。

板卡执行、tt-metal lowering、固件适配和厂商周期精度不属于本轮交付。若未来单独提出芯片精度或原生实现主张，再追加相应验证。编译器研究也不以 RTL/PPA 为前置；新增硬件和能耗主张需另立成本合同。

## 2. 只推进一条主线

**面向多 tile、双 NoC 和分布式 DRAM 的确定性 DFG，联合选择计算位置、数据分片与位置、合法 NoC 和发送窗口，研究共享资源与分离完成事件是否改变强静态计划的选择。**

研究单位是完整计算及数据搬运图。先从源算子的访问关系推导每个消费者实际需要的数据，再把这些数据映射到资源和生命周期。不能再次从 buffer footprint 推出 full all-gather；R12 的真实 2conv 纠错是强制回归案例。

最具体的待测耦合是：路由/DRAM channel 影响源读取与目标写入进度，二者又影响可复用源 slot、目标驻留与下一次预取；最少 byte-hops、最早发送或最早释放都不自动等价于最短完整 makespan。

以下对象暂不扩张：新增乱序硬件、动态触发器、完整 SDK、MoE 换题、3D memory 融合模型。3D 堆叠仍可在以后作为独立论文架构合同比较，不能通过给当前模型增加免费带宽制造收益。

## 3. 文献依据与贡献边界

[模型评估文献核查](../literature/model_based_evaluation_20260908.md) 区分论文实际采用的建模/验证方式与我们尚未完成的工作；[独立合同红队](../analysis/r13_model_contract_redteam.md) 给出最小模型及反解释。

- [STREAM §IV-C、VI](https://arxiv.org/html/2212.10612v2) 使用多核成本建模与设计空间探索。R12 固定的 2026 TETRA 源码是更晚的实现，不能把其全部能力归于早期论文。
- [SoMa §IV–VI](https://arxiv.org/html/2501.12634v1) 已有 tensor lifetime、预取/延迟写回和 buffer 分配的联合探索。因此“联合调度数据搬运”本身不是本项目的新贡献。
- [LATTICE v3 §V-B](https://arxiv.org/html/2607.17422v3) 明确使用确定性命令回放模型，已有 memory-plan-preserving 排程；它的单核、whole-residency 边界不自动覆盖多 tile 网络和分阶段访问。此处将其作为公开预印本与近邻工作，不暗示已获同行评议接受。
- [SCALE-Sim v3 §IX-B](https://arxiv.org/html/2504.15377v1) 已展示加入 DRAM stalls 后数据流排序反转。因此“更完整成本会改变排序”也是已知现象，本轮需要具名的多资源/完成事件耦合及超越强基线的证据。

模型方法成立不等于模型内的任何改进都有论文贡献。本轮必须分别回答：

| 命题 | 实验含义 | 能支持什么 |
|---|---|---|
| H0：正确模型与已有强编译器足够 | 给现有方法完整资源、合法生命周期和同样候选后，候选新方法无稳定优势 | 正常后端工程或负结果；应接受 |
| Hmodel：粗模型遗漏会改变合法计划排序 | 粗模型选出的计划在统一精细模型中有 regret；所有比较计划先通过同一正确性检查 | 模型适用边界和具体耦合证据；尚非新算法贡献 |
| Hcompiler：联合搜索仍有额外价值 | 在同一精细模型、同候选/能力和相同搜索预算下，P1 超过最强 P0 | 可继续研究的编译算法信号；新颖性仍须对近邻实现核查 |
| Hruntime：运行时信息有额外价值 | 需要事先定义静态无法知道的信息及其来源/成本 | R13 不开启此实验 |

在服务、输入和全部外生事件已知的确定性模型内，任一有限 runtime 执行轨迹都可记录成同样的静态动作次序与释放约束。只要静态候选空间允许该轨迹，runtime 不具备超越静态全局最优的信息优势。在线启发式击败有限预算的静态启发式，首先说明搜索质量差异，不能直接推出硬件必要性。

## 4. 模型必须显式表示什么

固定来源继续采用 R12 的 [dependencies.json](../r12/dependencies.json)。只建立一个资源/事件执行引擎，独立 checker 不复制优化器。现有 tt-npe 保留为限定范围的网络交叉参考，不增加 BookSim、Ramulator、gem5 全套平台作为前置。

| 部分 | 公开事实或确定的数学内容 | 必须另行登记的建模选择 |
|---|---|---|
| 图与数据 | 完整算子、分片访问、相同输入/输出、数学归约许可 | packing、分块、padding、初始驻留、代码/控制占用 |
| NoC | 固定物理 10×12 torus，NoC0/1 各自方向与维序；保留所有转发点；请求、响应、ACK 路由分别算 | flit 服务/路由延迟、VC 使用、仲裁与端点阻塞的明确实现 |
| 外存 | 六个三端点组，每组两个 1 GiB channel；端点别名不会创造带宽 | 有效带宽、读写切换、controller 排队与服务策略 |
| L1 | 固定文档中的容量、bank 和端口约束，区分两 NoC 的读写接口 | 地址到 bank 映射、代码保留量及未公开服务效率；不能把两 NoC 无依据合成一个 server |
| 计算 | 完整 MAC/逐元素工作量；选定精度模式的公开理论能力只作上界 | 分块利用率、启动费用、向量/SFPU 服务、局部数据供应；M=1 padding 不能免费 |
| 异步执行 | 下述分离事件及真实数据依赖 | 通知实现、命令发行资源/费用、credit 返回延迟与未知 NIU queue |

每个参数需记录值、单位、出处与代码行、类别（公开固定 / 推导 / 实验假设）、敏感性范围和适用结构。未知项可以作为模型假设继续实验；不得写成已测 Wormhole 参数。

时间用明确的 model cycle/tick。若换算成 ns，时钟比本身也要登记。NoC packet/flit、L1 和 controller 必须处在同一时间坐标。不能将 `bytes/bandwidth` 的聚合流体近似命名为完整周期精确模型。

固定来源中可直接采用的锚点包括：L1 为1464KiB/tile，16个bank各支持一次128-bit读或写/cycle；每NoC具有独立的两读/两写128-bit L1连接，bank冲突仍可能发生；NoC文档给出无拥塞时相邻router间9 cycles、NIU与直连router间约5 cycles。MatrixUnit文档给出标准1GHz与不同fidelity的理论能力，GDDR6文档给出每channel典型24GB/s理论上限。它们是容量、结构或理论界，不是已测持续服务率。[L1](https://github.com/tenstorrent/tt-isa-documentation/blob/5287a62727350bcef35f7b411d1b8a706172ec4c/WormholeB0/TensixTile/L1.md)、[NoC](https://github.com/tenstorrent/tt-isa-documentation/blob/5287a62727350bcef35f7b411d1b8a706172ec4c/WormholeB0/NoC/README.md)、[MatrixUnit](https://github.com/tenstorrent/tt-isa-documentation/blob/5287a62727350bcef35f7b411d1b8a706172ec4c/WormholeB0/TensixTile/TensixCoprocessor/MatrixUnit.md)、[DRAM](https://github.com/tenstorrent/tt-isa-documentation/blob/5287a62727350bcef35f7b411d1b8a706172ec4c/WormholeB0/DRAMTile/README.md)

### 分离完成事件

1. `issue`：任务已发行，不表示 payload 读取完成。
2. `source_last_read`：该源 span 的最后实际读取完成；源地址的下一次覆盖必须在其后。
3. `target_visible`：最后目标内存写入完成；NIU 接收或请求 sent 不能代替它。
4. `ack_observed`：发起方观察到相应完成确认。
5. `notification_observed`：消费者观察到该代数据的通知。
6. `consumer_last_read`：消费者最后一次读目标 span；接收 slot 才可复用。

`consumer_ready` 要同时满足目标可见与规定的通知观察；通知不属于 `target_visible` 的定义。重用源空间只需满足所有源读者完成，不能无理由强制等远端消费；反之 ACK 不证明消费者读完。控制动作占用的队列、存储和服务时间必须统一收费。

主模型采用有限缓冲、credit 和 backpressure 的离散事件服务，表示渐进的源读、注入、链路传输、目标写和控制反馈。具体 VC/仲裁/资源释放顺序必须在第一张性能图之前冻结。store-and-forward、零拥塞解析网络可作结构对照，不能暗中混入主模型。出现死锁或数值/所有权错误的计划判无效，不能当低性能合法样本计算均值。

## 5. 工作负载和实验矩阵

### 小图资格与穷举

延用四个活动 tile、两条 load→compute→peer→consumer→output 链、两代数据；两个源 slot 与接收/输出 span 分开计容量。R12 的 96 个空间/路由候选只作为种子，不冒称包含所有发送窗口与资源顺序。

小图将 tiling、位置、channel/endpoint、合法 NoC、事件锚定的有限发送窗口和资源顺序列成显式集合。所有方法使用同一集合。只有完成该离散全集的枚举，才称“该集合上的 exact optimum”；不声称任意连续发送时刻或所有架构上的全局最优。候选过大则缩小预登记集合或报告界/gap，不把超时 incumbent 写成最优。

部分读写验证使用每16B块不同的元素身份和值，跨代也不同；不再只用同一标量填充整个payload。主模型先覆盖对齐unicast read/nonposted write及其控制反馈，P0/P1采用同一动作子集；若未实现厂商multicast/其他网络模式，结论明确限定在该子集，不称已击败所有原生通信方式。

| 见证族 | 固定不变 | 改变的条件 | 必须看到的量 |
|---|---|---|---|
| 链路重合 | payload、访问关系、全部资源；对严格等量对照还固定含 request/response/ACK/通知的总 byte-hops | 合法路径的有向共享链路 | 逐 link 服务、排队、完整输出可见时间 |
| channel 与端点别名 | 总 payload、输入/输出位置合同和硬件预算 | 同 channel 多 endpoint / 同组另一 channel / 不同组 | 按物理 channel 的总服务，不按端点重复带宽 |
| 完成与复用 | 算术、地址容量、任务数及目标数据 | 合法源提前释放与保守 ACK 等待、发送窗口、接收 slot 归还 | 源/目标占有区间、通知、下一代覆盖、完整 makespan |

链路见证的等 byte-hops 必须核对全部实际包类；若完整协议下找不到严格相等的候选对，则记录每类流量差异并单独归因，不能把 R12 的 request-only 等量标签沿用为完整协议等量，也不能删去返回/通知流量以凑对照。

另加两个必须通过的回归：完整复制合同共享 bus 的守恒反例；真实 2conv 的 source affine/halo 需求。前者的 2048 服务界不能无条件套到后者；后者 49152-bit/384-cycle 只属于连续对齐所有权见证，并不证明某个实际 512-cycle 搬运协议。

### 完整模块

固定 Qwen3.5-4B 完整 MLP：`down(SiLU(gate(X))*up(X))`，H=2560、I=9216、M∈{1,32,128}。输入、三组权重和完整 down 输出均计量；不以 down N=128 切片或局部 transfer 为主指标。

主配置为 4/8 个活动计算 tile × 三个 M，共六项；每项均保留完整物理网络与相同的十二个 DRAM channel，允许强基线公平分布数据。四 tile 是 R12 的衔接规模，八 tile 是空间扩展对照；这不是在售 SKU 配置声明。活动坐标集及合法位置候选在实现阶段、看性能前登记。更大规模只在模型资格通过后作为另行标明的扩展。

主合同使用 cold weights：本次 invocation 开始时全部权重在已分配的 DRAM，必须支付实际读取。M=1 是单个已到达输入，不预给后续 token；M=32/128 的整批输入已存在。不能把 135 MiB 全权重免费预驻留到四/八 tile 的 L1。warm/跨 invocation 驻留如以后研究，另立精确容量与起终状态合同。

先用 CPU 软件 reference 完成数值资格。模型的三次矩阵乘使用 BF16 乘数和 FP32 累加；gate/up 的 FP32 结果经 FP32 SiLU/乘法后，在 down 输入边界显式按 round-to-nearest-even 转为 BF16，down 的输出为 FP32。该 cast 的任务、bytes、存储与执行费用对全部候选共同计入，不能一边保留 FP32 down 乘数一边使用 BF16 FPU 峰值估价。此处定义的是 Qwen 源代数上的具名数值模型，不声称逐位等同某个原生 kernel。

FP64 源代数用于误差对照；另用独立实现核对上述量化/归约合同。明确 SiLU 实现、分块归约树、seed、允许误差和 padding，所有候选遵守同一许可。小图可用逐元素精确值；完整模型使用确定性生成的测试张量，不要求下载已训练权重或执行 native kernel。

## 6. 强基线、候选方法和统一评价

**P0 必须是 portfolio 的最优合法结果**：正确移植的 STREAM/TETRA；通信感知 mapping/placement；合法融合、prefetch、双缓冲和 wait scope；固定 placement 后的发送窗口/资源顺序细化；至少一种 SoMa 风格生命周期与搬运顺序搜索。移植应保持原算法的定义并记录适配处，不能把任意自写启发式命名为原论文实现。

P0/P1 使用相同的精细执行模型 F、相同候选能力、buffer/队列/控制费用、数值合同及时间预算。P0 不能因名称“现有静态”而失去合法提前释放或发送窗口。若现有 TETRA 已能表达并求解所需联合问题，就直接使用其结果，接受 H0。

**P1 的待实现方法**：在相同候选集合中联合搜索 placement、路由、发送窗口与生命周期。先用小图 exact optimum 检验价值；有 residual 才采用求解器与事件执行器之间的迭代细化。正确性反例可生成合法性约束；一次拥塞慢执行只产生有依据的成本/下界或候选优先级，不得直接剪掉一个仍合法的方案。

预算在性能测试前冻结，按配置记录 evaluator 调用数、solver 时间/threads/seed、每阶段状态及 gap。启发式多 seed 用于衡量搜索不稳定性，不作为物理 timing 的独立样本。报告最好 P0、各组成方法、P1 和 exact/下界，不能只选择一个弱组成方法作分母。

粗模型和过度同步只作诊断消融。省略共享资源或错误地把 sent 当完成而得到的非法计划，必须拒绝；不能进入“合法性能提升”的分母。要量化粗模型排序误差，先用共同正确性合同生成全部合法候选，再让不同估价器排序，并统一交给 F 回放。

主指标是从共同模块入口到全部输出可见的 **modeled makespan**。辅助指标为逐层 bytes、源/目标/接收 slot 峰值、逐 channel/link/NIU 等待、compute-active 与实际发送/重排动作。编译时间单列；部署控制动作计入 makespan。没有付出能耗/面积建模工作时，不报告能耗/PPA结论。

同时报告 `final_ack` 与全部已发行请求/通知完成、credit/ID 回收后的 `quiescent` 时间。完整数值输出可见并不自动证明尾控制已结束；后续 invocation 或吞吐不得在协议尚未允许复用时免费开始。若某方案只缩短 output-visible 而延长清空时间，明确给出该取舍，不把前者称为完成态或稳态吞吐的无条件改善。

## 7. 没有板卡时如何验证模型

验证链不是“作者说有仿真器，所以本模型可信”，而是以下独立证据：

1. **数学守恒与功能**：实际需求覆盖、每份数据所有权、RAW/WAR/WAW、容量/credit守恒、请求/响应/ACK配对、边界条件与终止。R12错误事件反例必须继续被拒绝。
2. **可手算的小例**：单传输、真正独立链路、已知唯一瓶颈、同 channel 别名等；解析下界不得被执行时间突破。检查关闭争用时与显式解析服务一致。
3. **独立时间回放**：微图精细 tick/flit 检查器与主 DES 使用不同实现，核对事件与资源轨迹。证明的是模型实现一致性，不是芯片精度。
4. **限定跨工具检查**：与 tt-npe 比较双方共同表达的单网络负载、方向和拥塞趋势，先固定版本/参数/统计口径。NPE缺失的visibility、buffer lifecycle和DRAM协议不借其数值验收；不追着官方example的450改参数。
5. **参数和结构敏感性**：公开固定项不乱扫；未知服务效率、命令/credit延迟、队列与控制成本用事前范围。给出完整收益分布、最坏值与排序翻转边界；bank细化和另一网络服务结构单列。

参数不确定性不是随机物理噪声。先固定名义场景和一因素/交互角点，再分别做“每参数点允许重新编译”的设计适应性测试，以及“名义计划冻结、只改变评估参数”的失配稳健性测试。后者不能偷看测试点重新优化。不能只报告有利带宽点或把等价无噪声重复包装成 CI。

### 初始敏感性场景

采纳下列离散集合用于 R13 第一版模型研究，均为**研究场景而非实际芯片参数估计或置信区间**。若实现揭示某项重复计费或与公开约束矛盾，须在运行性能比较前修订并记录原因，不能看收益后更改。固定NoC参考点1GHz、link启动间隔1cycle、router hop取公开9cycle实例、公开router buffer容量；NIU邻接hop的约5cycle单列近似，不能与额外事务处理重算。

| 参数 | 名义值 | 预登记集合与含义 |
|---|---:|---|
| NIU本地数据服务效率 ηN | 0.75 | `{0.5,0.75,1}`×每NoC独立读/写32B/cycle上限；最小无bank冲突结构下的有效服务场景 |
| DRAM channel有效率 ηD | 0.75 | `{0.5,0.75,1}`×24B/参考cycle；读写共享每个物理channel的总预算 |
| 计算有效率 ηC | 0.5 | `{0.25,0.5,1}`×固定精度/操作形状/已计padding后的能力；向量、cast、pack/unpack分别计服务 |
| NIU内部数据buffer BN | 4 flit | `{1,4,16}` flit；未知结构场景，公开router buffer不改变 |
| credit返回延迟 | 18 cycles | `{9,18,36}`，从下游实际释放起计；在途预留和传播另记，禁止提前释放容量 |
| NIU额外事务处理 | 9 cycles | `{0,9,18}`；位置和每事务触发次数写入服务合同，不允许无说明地按每flit累计 |

先跑名义点加六轴各两档的13点单因素集合，再跑16个交互点：ηN、ηD各取`{0.5,0.75}`，ηC取`{0.25,0.5}`，credit延迟取`{9,18}`，其余保持名义值。小图先跑这些点；完整六配置在M0通过后先跑名义点，进入M2时均覆盖13点单因素与16点交互的去重并集，不能仅凭微图推断BN或额外NIU处理对完整模块的影响。该并集是M2的六参数失配评估域，不声称覆盖六轴全笛卡尔积或连续区间；未测试组合不纳入稳健性结论。参数集合是集合而非独立随机样本。

控制primitive先拆成具体服务，再冻结公共成本表，完整六配置在其余参数名义值下统一测试`{0.5,1,2}`倍率，也纳入M2失配评估域；零费用只作乐观控制。bank冲突/合法layout、仲裁tie-break和网络服务结构另外检查，不混成参数CI。服务效率的离散化须有明确budget累积/时间量化规则，避免逐flit粗暴取整产生未登记吞吐损失；M0独立回放与数值细化必须覆盖该规则。

## 8. 新的 M0 / M1 / M2 门

| 门 | 通过条件 | 失败后的动作 |
|---|---|---|
| M0：模型资格 | 上述功能、守恒、解析与独立回放检查通过；事件/资源假设有登记；三见证族确实触发 | 修正模型或收窄模型声明，不增加调度机制；不等待板卡 |
| M1：可识别残差 | 精细模型下，相同离散空间的 exact 小图揭示具名的模型排序/强P0搜索残差，并排除需求错误、资源增加与非法次序 | Hmodel成立但Hcompiler不成立时记录模型边界/工程结果；没有残差则关闭新算法投入 |
| M2：完整模块与稳健性 | 名义非退化配置中至少两项完整 MLP 净 makespan 改善≥3%；达到门槛的配置须在事前参数失配范围内保持正向，全部反转/失败配置均报告；M0仍成立 | 仅局部/极端收益则收窄结论；强P0吸收则接受H0；模型结构决定符号则先refine |

3% 是本项目保留的投入阈值，不是学界统一标准。旧“收益误差≤约1个百分点”不再解释成必须对板卡校准。若使用时间步/服务近似，约1个百分点可作为**相同模型下数值细化对相对收益的稳定性目标**；相同模型的独立实现应在明确定义的 tick 精度内吻合。参数敏感性范围另外报告，不能用数值稳定性代替物理参数可信度。

“模型内有稳定改善”“模型选择影响结论”“该Wormhole SKU有实际加速”是不同主张；本轮只评估前两项。若只剩已有方法正常接入模型，结论可以是可复现后端和负结果，不继续替P1寻找有利输入。
