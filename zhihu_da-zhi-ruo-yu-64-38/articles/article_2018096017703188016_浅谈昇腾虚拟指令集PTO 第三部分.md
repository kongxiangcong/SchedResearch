PTO ISA为下层的昇腾硬件进一步松绑，也许在未来的某一天，说不定谁就会猥琐发育，做出来一套捅到天的新型架构来。大家现在接入的越多，华子就会在下面就会玩的越野。

你也许会发现，PTO指令集构建了一套Abstract Machine，这个虚拟的机器的结构如下：

- CUBE-VEC从各自独立的Buffer，被抽象成了**一个共享的Buffer**。
- 两个标量被抽象成了一个**统一的标量**。
- MTE1，MTE2，MTE3这些不明所以的名称，抽象成了TMA，**只有TLOAD和TSTORE两条指令**

![image](https://pica.zhimg.com/v2-78ef8a74fb34c1a1b289d75cf0310d6e_1440w.jpg)

说不定这个虚拟的机器，将来也变成一个物理的机器呢

那跑在这个虚拟机器上的指令集，就是PTO虚拟指令集。这个指令集长啥样呢？现在还没有正式公布，但是可以在个人野仓里面一探虚实 [https://github.com/zhangstevenunity/PTOAS](https://link.zhihu.com/?target=https%3A//github.com/zhangstevenunity/PTOAS)

就是这套PTO汇编，通过PTOAS (PTO Assembler)工具，根据Tile的依赖关系和生命周期，插了set wait同步，分配了buffer地址，编译到了不同昇腾硬件的物理指令集。

## 黑科技：Tile Out-of-Order Execution

基于昇腾达芬奇架构这一套天然异步的Pipeline，PTOAS汇编器构建了一个虚拟的Tile级别的CPU。它把Tile当作普通的寄存器来看，把PTO指令当作CPU指令来看，在昇腾模拟出来了一套OOO执行引擎。

如果我们看一个普通的Superscalar CPU，它基本会有如下的模块：

- 跳转预测/控制流投机
- 寄存器重命名 Atag到Ptag转换
- ROB reorder buffer
- Issue Queue/寄存器保留站
- Register File

因此，在PTOAS内部，我们也把这一套CPU逻辑，靠软件模拟出来了。这样，上层的程序员就可以按照串行的逻辑写代码，而不用考虑TileOp之间的依赖关系检查和异步执行。

这一套逻辑，通过GPU的warp specialization可以解决。本质上，也是通过warp的异步协作，把一个乱序窗口顺序提交的逻辑组装起来。

## 在Tile OOO下Attention的理想流水长啥样

![image](https://pic2.zhimg.com/v2-6c2cefbb7f52101d1e718fe867cf8bed_1440w.jpg)

如果PTO TileOP可以随意乱序执行，那么我们就可以把一个Flash Attention写成了如上的流水。通过调整矩阵乘和softmax和global update的tile size，我们能够让QxK，PxV，softmax，GU这四个kernel在执行时间上总体上差不多，让Cube和Vector做到最大程度的交叠。把FA的各种shape调到MFU 90%不是梦。

Cube的利用率就是我们所谓的MFU，那么只要让大家铁索连环绑在一起共同携手奔向K轴就好。

有人会问，这种固定的数据流，为啥不用CGRA去加速？上面的流水线很固定，我们就可以让它流水进，流水出啊？

当然英伟达买了Grok后，LPU就已经朝着这个邪修上走上了不归路了。

## 什么是新同构？

在华子一个全都要的公司里面，核也避免不了来自于多种业务的需求。因此，即将问世的950架构成长了一个变形金刚。左手SIMD，右手SIMT。一只手适合做规整的计算和Reduce。另外一只手适合做Gather和Scatter。

![image](https://pic1.zhimg.com/v2-5b39b589e87b7c3fc53d02a74738628c_1440w.jpg)

如果把这个变形金刚外衣扯开，展现给我们的是一个复杂的系统。

- 我们为了支持MX-FP8和MX-FP4增加了BT buffer，增加了FP （Fixpipe buffer)，用于各种数据类型的量化。
- 我们在Cube-Vector之间增加了一个Shared Scalar Buffer，用于Cube Vector快速交互。我们有一个快速的通道，可以使能Attention的QxK->softmax和sum到PxV回路上。

![image](https://pic2.zhimg.com/v2-dac931b938a0a1fc0269068931ec2f7d_1440w.jpg)

- 我们给Vector核增加了两个前端，一个SIMD，一个SIMT。各自有两套寄存器，但是共享UB单元。
- 我们增加了一个Gather DMA，用于解决被广大客户诟病的Gather难用的问题。
- 我们核内，有5个标量单元
- 嗯，我们的矩阵分形也变了模样

这么复杂的系统，我们不会期望普通的程序员会在上面进行极致手写编程。

目前看来，最强的Claude Code Opus 4.6/Codex GPT5.4 1M Context window都搞不定。

这个就是我们说新同构。新同构的背后，反而变得更异构了。

只有PTO虚拟指令集，能够让你把这个复杂的系统，通过简单明了的方式使用起来。

## PTO指令集的背后？

在PTO ISA的950后端上，你可以看到这些指令的背后，就是950的DSA们。

- tload, tstore
- tpush tpop
- tgather, tscatter
- tmov
- textract, tinsert

我个人认为，每个DSA都是华子精心设计的小心机。但是，即使你看了AscendC和CCE手册，也不知道该如何下手。要想把他们用好，还是得要问当初设计它的同学们 :)
