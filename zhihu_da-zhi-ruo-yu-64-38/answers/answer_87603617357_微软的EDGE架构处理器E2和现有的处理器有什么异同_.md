# 微软的EDGE架构处理器E2和现有的处理器有什么异同？

- 类型：回答
- 问题：微软的EDGE架构处理器E2和现有的处理器有什么异同？
- 原文：[知乎回答](https://www.zhihu.com/question/282048635/answer/87603617357)

EDGE处理器，设计理念源自于UT Austin大学设计的TRIPS处理器。它的设计理念就是**块指令集(Block Instruction)**。

[The TRIPS Project-- Tera-op Reliable Intelligently advanced Processing System](https://link.zhihu.com/?target=https%3A//www.cs.utexas.edu/~trips/publications.html)

简单来说，传统的CPU是一条一条指令执行，块处理器就是将程序分成一块一块的执行。可以把一个块指令当做一个小任务，里面指令基本上是一个基本块的粒度，约7~8条指令。

这个方向，中科院计算所的安红老师，也做了很多年的研究。安红老师，和胡伟武老师，包云岗老师，分别走了三个不同的指令集方向~

[TRIPS指令集手册](https://link.zhihu.com/?target=https%3A//www.cs.utexas.edu/ftp/dburger/papers/TR-05-19.pdf)

CPU把执行的粒度调高到了以后，就可以把自己的ROB(Reorder buffer)做到很大，甚至可以到一千条指令的乱序执行。通过块指令的并行，获取比传统CPU更好的性能。

![image](data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' width='984' height='612'></svg>)

块处理器的原理

其最主要的作者Doug Burger从University of Wisconsin毕业后，到了UT Austin当了教授，主要负责TRIPS处理器的设计。后来他加入微软，并忽悠这个软件公司去做一个硬件的核，叫做EDGE处理器(不是EDGE浏览器)。

我记得是2018年的ISCA Keynote上，这位老哥秀了一把用EDGE处理器跑通Windows10的Demo，让一堆人啧啧称奇（包括我）。后来我专门去问了他本人，才发现，这个处理器是作为一个加速器挂在一个x86 CPU才跑起来的操作系统。

EDGE处理器的想法挺好，但是毕竟是个学术玩具，太傻太天真，很多逻辑上也讲不通的地方，也许只有不懂硬件的微软上了这个当。某次我在bilibili上划水时，发现过某位民间科学家发明的[祝氏计算机](https://link.zhihu.com/?target=https%3A//www.bilibili.com/video/BV1vk4y1U7W4%3Fvd_source%3Da37915fd2221aa121c15e8369b8677c8)有异曲同工之妙。这位祝同学，也把他的新型指令集架构叫做块指令。

![image](data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' width='2374' height='945'></svg>)

## EDGE处理器如何不靠谱

### 1：CPU是时延敏感，不是吞吐敏感

EDGE处理器强行的把不同的块指令分散到多个小型的执行引擎上执行，想要用多个小核加速一个核的效果。这个概念的确在2000年左右时，单线程CPU遇到Frequency Wall时流行的解法。多个小核通过Fusion，合成一个大核，这种做法不香吗？

![image](data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' width='648' height='449'></svg>)

但是实际上，大部分现有的程序，都是时延敏感。程序计算的关键路径跨了核，对性能的影响非常大。为了降低时延敏感的影响，硬件需要把时延关键路径放到一个后端核上执行。结果就需要把调度搞得很复杂。

### 2：CPU的跳转预测足够准才能解锁指令并行度

EDGE处理器把执行的粒度调高到块了以后，就可以把自己的ROB(Reorder buffer)做到很大，甚至可以到一千条指令的乱序执行。但是这建立在**连续的块指令预测都是基本正确的前提**下。

也就是MPKI (mispredict per kilo instruction)需要足够低，才能让指令窗口内装满预测对的指令。

否则指令窗口内装满了投机执行错误的指令，等到后续被Flush掉，这样反而白白浪费的功耗。

所以，EDGE的作者也承认，**与其花面积用在多核并行上，不如把面积花在前端上**，增加BTB的容量，增加ICache容量和预取，增大TAGE的RAM等带来的性能收益，远远大于并行带来的收益。

### 3：前端并行，但是后端并不并行

EDGE处理器想保证单线程顺序的访存语义，在多个执行引擎上，想让块指令的访存读写依然保证源程序的weak memory order序。为此，他们花费了大量的精力，用在设计Lazy Commit的LSU上。具体论文可参考：[Scalable Hardware Memory Disambiguation for High-ILP Processors](https://link.zhihu.com/?target=http%3A//www.cs.utexas.edu/users/cart/trips/publications/micro03_lsq.pdf)

这个设计就差点进入Hardware Transactional Memory的领域，本来不太靠谱的架构设计上，如果又叠上了更不靠谱的HTM，那就基本上歇菜了。

如果让多个后端干脆就乱序读写内存呢？那这样和多线程有什么区别呢？那还不如让程序员标记一下某个循环，加个openmp parallel for来的简单。

## 那如何让EDGE处理器变得更靠谱呢

EDGE处理器，如同昙花一现，淹没在历史的车轮中。

让硬件自动并行化，这是个历史上的老大难问题。

若要是能简单解决，那就解决了CPU领域的圣杯级的multi-billion问题。

我们有趋近于它的解法，但是并不完美。
