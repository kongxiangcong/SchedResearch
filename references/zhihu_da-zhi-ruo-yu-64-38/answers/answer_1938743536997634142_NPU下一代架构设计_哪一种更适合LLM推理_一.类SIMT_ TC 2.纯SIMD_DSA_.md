# NPU下一代架构设计，哪一种更适合LLM推理？一.类SIMT+ TC 2.纯SIMD+DSA？

- 类型：回答
- 问题：NPU下一代架构设计，哪一种更适合LLM推理？一.类SIMT+ TC 2.纯SIMD+DSA？
- 原文：[知乎回答](https://www.zhihu.com/question/1932387258159301620/answer/1938743536997634142)

本质上是静态调度和动态调度的区别，而不是SIMT和SIMD的区别。

我认为下一代架构一定是动态调度的架构会赢。

这个争论，很早就在superscalar vs VLIW(DSP)的战争中分出过胜负。硬件通过多线程，或者OOO调度排的流水，终究是胜过了编译器或者Excel静态排的流水。

在大模型时代，我们再一次面临了矩阵乘+softmax类型的计算流水，执行的粒度变为了SRAM级别的共享和同步。同理，无论是SIMT还是SIMD都解决不了大模型里面天生的“拧来拧去”的数据流。

不要小看矩阵乘的难度。

(32x32x32)的Tile和(33x9x61)的Tile排出来的流水完全不同。

我们的维度是任意形状的，因此对应矩阵乘+转置+向量+矩阵乘的这样的计算方式，实际上谁也不太适合。

目前看到的最好方式，就是增强“各个层级”的层次化控制。

- 核与核之间增强Buffer的互相访问和细粒度共享
- 任务之间在多个核上做MPMD的任务动态调度
- 核内需要增强DMA, 矩阵，向量tile的并行和动态调度
- Tile内部需要增强Subtile分型的动态调度
- Subtile内部需要增强SIMD的指令流水乱序执行
- SIMD内需要增强Shuffle指令的编排(byte级别)

这玩意儿不是一个简单的SIMT编程模型就能搞定的。

如果SIMT剥离了Warp调度以后，就没啥性能优势了，SIMD也能做到相同的效果。

更何况类似于tile lang，cutile，triton这样的编程模型，也就是牵引生态朝着层次化调度的方向演进，程序员也不太想去写cuda kernel这样的代码(说实话不好写)。
