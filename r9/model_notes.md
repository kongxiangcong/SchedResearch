# R9 executable path conventions

`model.py` reads the one numeric hardware contract. `build_graph` returns JSON-compatible data; `simulate` has no cross-run state. The simulator accepts manually constructed graphs as well as the fixed Qwen graph, so a separate checker can enumerate tiny cases without copying the generator.

Each graph DMA node is one command. Commands become eligible only when every graph dependency completes; a fixed node priority admits any ready command into the eight available command slots. No unready command occupies a slot. Each cluster issues one next packet in round robin over admitted commands that still have packets, while the configured outstanding limit, four transport slots, and each slot's byte capacity permit. Commands retain their slots until every packet is destination-visible. Completed command removal preserves the next round-robin position.

A packet's transport slot is held from acceptance through visibility. Read packets pass through request latency, shared EXT, cluster DMA, then visibility. Write packets pass through latency, cluster DMA, shared EXT, then visibility. Local DMA charges every multicast recipient's bytes. Shared EXT defaults to round robin among nonempty cluster queues and FIFO within each cluster. An explicit single-action counterfactual may select any currently eligible EXT packet; its fixed charge delays that packet's EXT service and holds EXT arbitration until its finish. The counterfactual rebuilds all subsequent endogenous events. All same-time completions are applied before any admission or service decision.

The background removes EXT service during one fixed absolute interval in every period. An in-progress packet resumes after a reserved interval; other model packets cannot displace it. `external_start` is arbitration plus optional action cost; `external_segments` gives the actual available service intervals. No local-DMA or compute bandwidth is removed by this background abstraction.

Common external regions are `ext_x` row-major `[M,K]`, `ext_w` row-major `[N,K]`, and final `ext_y` row-major `[M,N]`; addresses are byte offsets within the named array. Gather is an explicitly admitted 2D transfer capability: its packets enumerate discontiguous original row spans and compact local destinations. Row mode ends each packet at an external row boundary. Every external span is independently rounded to the bus beat. No existing repacking or peer path is assumed.

Each core statically reserves X slots, W slots, FP32 partial-output storage, and (where required) received FP32 storage. Per-core absolute VMEM addresses start above the hardware's reservation. Reused input slots depend on the completion of every earlier compute reader; prefetch depth can impose an earlier ordering restriction. Resident X occupies one full shard and is transferred before its dependent computations; `order` does not change resident-X admission priority. Resident mode still buffers W. C2K adds two disjoint scratch allocations held throughout the run, explicit source write and destination read commands, and a reduction charging `max(adds/rate, 3P/operand_rate) + startup`. This conservative full-run scratch allocation avoids an unmodelled allocator or recycling policy.

`resource_lower_bound` takes the maximum of an ideally continuous shared-EXT service curve from time zero, aggregate DMA cycles for each cluster, and aggregate compute/reduction occupancy for each core. It deliberately ignores dependency, latency, visibility, and packet-window costs, so it is optimistic; no critical-path tightness claim is made. The bound is per graph and is not a proof of the best mapping, layouts, or algorithms outside the declared finite space.

Detailed runs expose graph regions/dependencies, per-packet acceptance/source-last-read/service/visibility times, command slot intervals, compute operation intervals, and each eligible EXT choice. Non-detailed runs execute the same event path. Output time is the maximum visibility time of all final disjoint Y commands. This is a reference-cycle model, not measured host elapsed or hardware acceptance.
