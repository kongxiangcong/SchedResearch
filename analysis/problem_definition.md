# R3：研究问题与可证伪边界

日期：2026-09-05。目标是端侧多核、多 cluster、多 chip NPU 的体系结构研究。R1/R2 是输入证据，不是待复制的架构；llmSched 源码不在本目录，本轮不声称验证它的现状。原始文档审计见 [r1_r2_audit.md](r1_r2_audit.md)。

## 1. 研究对象

给定任务图 G=(V,E)，编译器选定 placement m、地址 a、资源需求 r、数值/可见性约束，生成合法执行合同 K。硬件只从已被许可的动作中选择启动时间和局部顺序。研究问题是：在同样的计算、存储、通信预算下，完成信息能否改善一个已经很强的静态计划，改善多少，需要付出多少有限状态和控制带宽？

“知道完整图”不等于“知道未来”。但是，“不知道每次完成时间”也不等于“存在可利用的调度机会”。必须同时出现：

1. **残余不确定性**：条件于已知 shape、mapping、地址、资源、输入类别后，仍有无法提前确定的延迟或到达次序。
2. **合法替代动作**：等待期间有独立且资源可行的任务；若关键依赖是一条链，ready dispatcher 无任务可选。
3. **结果敏感性**：替代执行改善端到端关键路径或稳态吞吐，而非只把非关键任务挪动。
4. **可见且及时的信息**：硬件看到 completion/credit 后，决策仍来得及；收益大于唤醒、派发、元数据读取及同步代价。

这是机会的必要检查，不是四项满足就必然提速的定理。贪心启动非抢占后台任务可能堵住稍后到达的关键任务。

## 2. 必须分开的五个决策

| 决策 | 静态掌握程度 | 本轮处理 |
|---|---|---|
| 算什么、切多细 | 常可静态确定；MoE路由/提前停止有数据相关性 | synthetic与LLM/DiT结构motif；数据相关路由仅用场景实例化，不宣称完整动态控制流 |
| 放在哪里、数据在哪 | 已知mapping/地址可保持稳定 | 主比较固定mapping和地址；不把迁移收益算成顺序收益 |
| 哪些先后关系不能破坏 | data、alias、数值归约、通信可见性可编译 | typed edges；data-ready与resource-ready分开 |
| 在合法序中选哪一个 | 延迟确定时可离线优化 | 强静态候选搜索和小图枚举；同硬件同图 |
| 何时真正开始 | 受完成事件和资源状态影响 | 所有实际baseline都self-timed；绝对时间表只作理论端点 |

一个按固定顺序、遇到未完成依赖就等待的硬件已经有运行时控制。需要测的是**增加选择自由度**，不是把它与没有任何完成检测的机器混比。

## 3. 性能界与信息价值

对固定合同 K 和随机环境 Z，定义：

\[
T_S=\min_{s\in\mathcal S(K)}\mathbb E_Z[T(s,Z)],\quad
T_D=\inf_{\pi\in\Pi_{causal}(K)}\mathbb E_Z[T(\pi,Z)],\quad
T_O=\mathbb E_Z[\inf_{\pi\in\Pi_{clairvoyant}(K)}T(\pi,Z)].
\]

这里clairvoyant集合允许在相同合同、资源和动作限制下读取未来，包含全部causal策略；causal集合又包含静态策略。在这些集合包含关系成立、硬件资源相同且忽略额外开销时，有 T_O≤T_D≤T_S。对本轮固定每task服务时间、固定mapping、一元资源bundle、非抢占且零控制开销的小图，任一可行执行可投影成资源顺序，因此才能以穷举静态资源顺序计算每场景oracle。若访问顺序改变cache/DRAM服务时长，不能不加证明沿用这个等价。实际的 B/C 只是具体启发式，不满足“必须优于最优静态”；加入控制成本后也没有这种保证。按真实未来延迟重排的启发式是 **clairvoyant heuristic**，不是数学 oracle，更不能把它当 T_O 的精确值。

即使静态编译器知道延迟分布，通常也有 E[min]≤min E。严格不等式来自不同运行场景需要不同顺序；不要求存在地址复用、重尾分布或非常多的核。R2 原引擎上的四任务有限分布反例见审计报告。

资源下界：T≥max(最长真实依赖路径、各资源需求量/容量)。在所有策略都把唯一瓶颈资源持续占满、没有次序相关的下游关键路径变化时，增加 OoO 很可能无收益。若一个全局拖延让所有可替代任务同时失去资源，独立性假设也失效。

## 4. 三类体系与实际baseline

| 体系 | 编译器 | 硬件 | 地位 |
|---|---|---|---|
| Fully Static | 图、placement、地址、操作顺序，可含精确时刻 | 按计划执行；严格版本需要可预测资源 | 理论端点；不能只用弱绝对时刻表作为论文基线 |
| Strong self-timed static | 强离线顺序、显式依赖、预取/重叠规划 | 完成检测、固定资源队头、已有DMA仲裁 | A/A2，最重要的现实对手 |
| Hybrid | placement、地址、legal partial order、resource footprint、priority | 有限窗口中的ready选择，completion/credit驱动 | B；C仍固定mapping，只增加运行时选序逻辑 |
| Fully Dynamic | 操作或任务、输入地址及语义 | 动态依赖发现、placement和调度，可能迁移/一致性 | 本轮设计分析对照；**未实现**，不能把C叫Fully Dynamic |

分布式任务图并不意味着硬件动态分析完整图；异步运行也不意味着同一engine内乱序。术语表见 [design_space.md](design_space.md)。

## 5. 本轮回答与未回答

本轮建立可解释的合成存在性/反例、强静态对比、受限控制开销与成本模型，判断值得继续测量的机制。它不能给出端侧产品预测、工艺面积/功耗结论、完整模型精度或跨芯片硅后性能。没有真实task trace时，“uncertainty到底有多大”只能是待测参数，不能用人为随机数回答。

Hybrid 是独立可研究的设计空间，但范式本身不新。论文候选必须定位到**何处需要动态、要暴露多少合法自由度、有限state/事件带宽如何逼近收益上限**的具体机制，而不是重新命名scoreboard。
